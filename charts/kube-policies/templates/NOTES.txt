## FIPS 140-3 and the internal token

Images are built with the Go FIPS 140-3 module and default to fips140=on. For
production set FIPS as mandatory:

    helm upgrade --install {{ .Release.Name }} <chart> -f values-production.yaml

This injects REQUIRE_FIPS=true so each binary aborts at startup if the validated
module is not active.

To rotate the shared internal bearer token with no downtime, follow
docs/runbooks/internal-token-rotation.md (two-token window: current + previous).

Tamper-evident audit log (AU-9): set audit.integrity.enabled=true and supply a
CSPRNG-generated audit.integrity.key (or pre-create the {{ include "kube-policies.fullname" . }}-audit-integrity
Secret). Each record then carries a sequence + HMAC chain; verify a log offline
with audit.VerifyChain. To rotate the HMAC key, update the Secret/value and
helm upgrade — the checksum/audit-integrity annotation rolls the pod so the new
key is loaded. NOTE: records written under the old key still verify only with the
old key; archive the retiring key alongside the segment it signed.

## TLS Configuration — Admission Webhook

Four modes are supported for webhook TLS bootstrap (evaluated in order):

1. **lookup-preserve** (upgrade idempotence): if Secret {{ include "kube-policies.fullname" . }}-admission-webhook-certs
   already exists in the cluster, its bytes are preserved unchanged. Requires
   `get secrets` RBAC on namespace {{ .Release.Namespace }} for the Helm service account.

2. **inline-pem** (tls.autoGenerate=false + tls.caCert/cert/key set): supply PEM-
   encoded certificates via --set-file admissionWebhook.tls.{caCert,cert,key}.

3. **autoGenerate** (default, tls.autoGenerate=true): chart generates a self-signed CA
   and leaf certificate (365-day expiry, 5 DNS SANs + IP 127.0.0.1). On the first
   install a one-time extra rolling restart occurs as the checksum/webhook-certs
   annotation transitions from "initial-install" to the stable Secret hash.
   DEMO-ONLY: this path uses sprig genCA/genSignedCert (fixed RSA-2048/SHA-256,
   below the FedRAMP-Moderate bar — see docs/compliance/crypto-standards.md).
   Do not use it in production.

4. **cert-manager (recommended for production, certManager.enabled=true)**: the chart
   renders an Issuer + Certificate (ECDSA P-256, CRY-WU-09/11) that provisions Secret
   {{ include "kube-policies.fullname" . }}-admission-webhook-certs, and annotates the
   ValidatingWebhookConfiguration with cert-manager.io/inject-ca-from so ca-injector
   populates the caBundle (no inline Secret or caBundle is rendered). cert-manager MUST
   be pre-installed in the cluster; `helm template` renders the CRs without it, but a
   real install/upgrade will hang until the Certificate goes Ready. See
   values-production.yaml.

If none of the above applies, the chart fails at render time with a remediation
message pointing at scripts/gen-webhook-cert.sh (manual certificate generation).

Mutual TLS (CRY-WU-04): set admissionWebhook.tls.clientCA to the PEM of the CA that
signs the kube-apiserver's webhook client certificate to enforce RequireAndVerifyClientCert
on the :8443 listener. Empty (default) leaves the listener server-auth-only.

## Cert Rotation

Self-signed certificates expire after 365 days. To rotate:

  kubectl delete secret {{ include "kube-policies.fullname" . }}-admission-webhook-certs -n {{ .Release.Namespace }}
  helm upgrade {{ .Release.Name }} <chart> --reuse-values

The checksum/webhook-certs annotation on the admission-webhook Deployment detects
the Secret change on the next upgrade and triggers a rolling restart automatically.

## Image Registry

Two image conventions are used in this chart:

* admission-webhook + policy-manager: registry defaults to docker.io; repository is
  host-less. Override image.registry to point at a mirror.

* dashboard: repository defaults to ghcr.io/Jibbscript/dashboard (fully-qualified).
  Setting dashboard.image.registry on top of a fully-qualified repository is DETECTED
  and the registry is SUPPRESSED to prevent double-prefixing. To use a mirror, set
  dashboard.image.registry=<mirror> AND dashboard.image.repository=kube-policies/dashboard
  (host-less), or leave registry empty and override the full repository instead.
